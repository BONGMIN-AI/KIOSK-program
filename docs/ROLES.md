# 역할 분담과 인터페이스 계약

> **현재 상태: 잠정 보류.** ABC 역할 패키지와 개인별 숙제는 배포하지 않는다. 차기 회의에서는
> 팀장이 구현된 BASE와 전체 흐름을 시연하고, 팀원 모두가 아이디어와 기능의 필요성을 이해하는
> 데 집중한다. 아래 내용은 나중에 실제 분업이 필요해질 때 참고하는 보존 문서다.

## 핵심 원칙
1. **파일이 아니라 '함수 계약'으로 나눈다.** 남의 코드 내부를 몰라도, 약속된 함수만 호출하면 되게 한다.
2. **첫날부터 가짜(Fake)로 개발한다.** 다른 사람 부분이 아직 없어도 막히지 않는다.
3. **자기 영역 밖은 건드리지 않는다.** 필요하면 PR 코멘트나 팀장에게 요청.
4. 모두 `MemoryVault` 로 개발하고, 통합할 때만 진짜 `Vault` 로 바꾼다.

## 10월 21일에 정할 담당

역할부터 나누지 않는다. 먼저 아이디어를 고르고 흐름도와 와이어프레임을 함께 그린 뒤,
각자가 흥미를 느낀 영역을 듣고 아래 경계를 기준으로 나눈다.

| 영역 | 폴더 | 이미 있는 BASE | 회의 뒤 확장 후보 |
|---|---|---|---|
| 통합·보안 | `core/` `tools/` `app.py` | 암호화 저장, 로그인, 감사 로그, 전체 연결 | 예외 처리와 발표 시나리오 |
| 계산·데이터 | `domain/` | 장바구니, 결제, 회원, 주문, 메뉴 50개 | 선정한 간판 아이디어 계산 |
| 화면(TUI) | `app.py` `ui/` | Textual 화면 전체 흐름 | 와이어프레임 반영·접근성 |
| 카메라 | `face/` | OpenCV 얼굴 등록·로그인과 실패 폴백 | 정확도·사용성 보정 |

## 계약 (변경하려면 팀장 승인)
```python
# 저장소 (팀장)
vault.read(name, default=None) -> 데이터
vault.write(name, data) -> None

# 검증 (팀장)
normalize_phone(raw) -> "010-xxxx-xxxx"   # 잘못되면 ValueError
mask_phone(phone) -> "010-****-5678"

# 2차 인증 - auth.unlock(..., second_factor=함수) 에 그대로 꽂힌다
verify_face(on_status=print) -> bool       # on_status(문구) 로 "정면에 서 주세요" 같은 안내 전달

# KIOSK 계산
payment_status(total, cash) -> 결제 가능·부족액·거스름돈
complete_order(vault, cart, cash, customer_id=None) -> 주문 딕셔너리
```

## 작업 규칙
- 브랜치: `feature/domain-*`, `feature/ui-*`, `experiment/face`
- 합치기 전: 테스트 3개 통과 + 팀장 리뷰 1회
- 자기 기능을 **2분 안에** 설명할 수 있어야 한다 (발표 때 본인이 설명)
