# BONGMIN CAFE KIOSK BASE

수업 과제 요구사항을 실제로 실행해 볼 수 있는 **Textual 터미널 KIOSK 기본 뼈대**다.
원본 `Desktop/team_base`는 건드리지 않았고, 이 폴더가 KIOSK 전용 작업 복사본이다.

## 지금 구현된 BASE

- 운영자 시작 로그인과 암호화된 JSON 금고
- 6개 카테고리(커피·디카페인·논커피·차·에이드·디저트), 메뉴 60개, 메뉴별 카페인(mg) 값 (디카페인은 0)
- OpenCV 카메라 기반 회원 ID+얼굴 로그인과 비밀번호 폴백, 비회원 주문
- 아이콘 카테고리 탭과 메뉴 타일, 옵션 선택(HOT/ICE·M/L·샷·시럽·수량)
- 장바구니 수량 ＋/－·삭제, 옵션별 줄 구분, 같은 메뉴 재고 합산 검사
- 현금 누적 투입·부족 시 결제 차단·투입 취소 반환, 거스름돈과 지폐·동전 단위 안내
- 회원 데이터 카드, 전화번호 자동 형식 변환, 알레르기 경고
- 결제액 1% 포인트 적립, 5회 방문 쿠폰 발행, 쿠폰 1장·포인트(100P 단위) 사용, 대기 주문번호와 영수증
- 회원 가입 2단계: ① 이름·아이디·비밀번호·비밀번호 재입력(* 표시)·전화번호·알레르기(검색+체크 목록)·동의를 세로로 입력 ② 얼굴 등록에 동의한 사람만 얼굴 등록 화면(안내 + 큰 거울형 카메라 창), 동의하지 않으면 바로 메뉴
- 알레르기 목록: 식약처 표시 대상 19개 항목(조개류 세부를 따로 세면 22종) + 카페용 2개(기타 견과류, 참깨)
- 운영자 로그인(ID+비밀번호 또는 ID+얼굴), 메뉴 추가·수정·삭제(2번 눌러 확인)·품절 전환, 마스킹된 회원·주문 조회와 검색
- KIOSK 종료는 운영자만 가능 (손님 화면에서 Ctrl+Q 차단)
- 운영자 포인트·이벤트 설정: 기본 적립률, 사용 단위·최소·최대 비율, 방문 쿠폰(N회마다·금액·유효 일수),
  기간 이벤트(날짜·요일·시간대·카테고리·적립률·주문당 보너스·최소 결제액·켜기/끄기)
- 운영자 회원 포인트 조정(사유 필수) + 회원 카드에 포인트 내역 저장, 운영자 행동은 해시 체인 감사 로그에 기록·무결성 확인
- 손님 화면 다국어(한국어·English·日本語·中文), 고대비, 큰 글자. 회원은 설정이 회원 카드에 저장되어 다음 로그인 때 자동 적용
  (큰 글자는 터미널 글꼴 크기를 바꿀 수 없어 버튼·칸을 키우고 굵게 표시한다. 글꼴 자체는 터미널에서 Ctrl+휠로 키운다)
- 무작위 움직임 2개를 요구하는 데모용 위조 방지와 테스트 전용 `FakeFace`

시연용 회원은 `bomin`, `member1`, `member2`, `member3`이고 초기 비밀번호는 모두
`1234`다. 얼굴 특징은 초기 데이터에 들어 있지 않으며 본인의 동의를 받은 뒤 각자 등록한다.

아직 정하지 않은 **간판 아이디어 1개와 보조 아이디어 최대 2개**는 넣지 않았다.
10월 21일 회의에서 고른 뒤 이 BASE 위에 연결한다.

## VS Code에서 실행

처음 실행하는 경우에는 `RUN_PROTOTYPE.md`의 단계별 안내를 그대로 따른다.

VS Code에서 이 폴더를 연 뒤 `터미널 → 새 터미널`을 누르고 아래를 한 줄씩 실행한다.

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python tools/reset_data.py --yes
python app.py
```

초기화 명령이 새 관리자 ID `admin`을 만들며 비밀번호는 터미널에서 직접 정한다.
프로그램 첫 화면에서 같은 ID와 비밀번호를 입력하면 KIOSK가 열린다.

테스트는 다음 명령으로 실행한다.

```powershell
python -m unittest discover -s tests -v
```

## 초보자가 알아둘 실행 흐름

```text
app.py 실행
  → 운영자 로그인으로 암호화 금고 열기
  → 회원 / 비회원 / 회원가입 / 운영자 메뉴 중 선택
  → 메뉴 → 옵션 → 장바구니
  → (회원만) 쿠폰·포인트 사용
  → 현금 결제 (부족하면 추가 투입)
  → 주문·재고·회원 카드 저장
  → 영수증과 대기번호
```

화면은 `app.py`, 계산은 `domain/`, 암호화·저장은 `core/`에 있다. 화면을 바꾸더라도
계산과 저장 코드를 다시 만들 필요가 없도록 분리했다.

## 데이터 안전 규칙

- `data/`, 키, 얼굴 자료는 GitHub에 올리지 않는다.
- 고객 정보는 `vault.read()`와 `vault.write()`로만 접근한다.
- 데모 4명의 전화번호와 이름은 가상값이다. 실제 팀원의 얼굴·실명은 동의를 받은 경우만 쓴다.
- 얼굴 인식이 실패해도 전화번호·ID 경로로 주문할 수 있어야 한다.

자세한 흐름과 회의용 종이 스케치는 `docs/FLOWCHART_AND_WIREFRAME.md`를 본다.

## 얼굴 등록과 위조 방지

앱에서 `회원 주문`으로 들어가 회원 ID·비밀번호를 입력하고
`비밀번호 확인 후 얼굴 등록`을 누른다. 또는 터미널에서 다음을 실행한다.

```powershell
.\.venv\Scripts\python.exe tools\check_camera.py
.\.venv\Scripts\python.exe tools\register_face.py --login-id bomin
```

카메라 창(왼쪽 카메라 + ROI 타원, 오른쪽 단계 안내)에서 얼굴을 타원에 맞춘 뒤
`고개 왼쪽으로`, `고개 오른쪽으로`, `가까이` 중 무작위 동작을 따라 하고 정면으로 돌아오면 된다.
등록은 동작 2개, 로그인은 빠르게 1개다. 고개 돌림은 YuNet의 눈·코 위치로 좌우 각도를 추정해
판정하므로 몸을 옮기지 않고 고개만 돌려도 된다. 실행 때마다 동작이 달라 정지 사진을 그대로
비추는 공격을 줄인다. 이 방식은 수업 시연용 활성 생체 확인이며
영상 재생이나 정교한 3D 마스크까지 막는 상용 보안 기능은 아니다.

카메라 프레임과 얼굴 사진은 저장하지 않는다. SFace 특징값만 기존 암호화 금고의
`face_profiles.json.enc`에 보관한다. 등록·로그인이 실패하거나 카메라를 사용할 수 없으면
비밀번호 로그인을 사용한다.
